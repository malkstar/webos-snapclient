Snapclient plays audio streamed from a Snapcast server on an LG webOS TV with millisecond-accurate multi-room sync.

Requirements

  • A rooted TV with Homebrew Channel (the app uses HBC's root exec service to run the daemon — that's why it says root required)
  • A Snapcast server on your network (snapserver / Music Assistant / Snapcloud …)

Getting started

  1. Open the app once. Scan discovers Snapcast servers via mDNS (or type the address).
  2. Save, then Start. The status line tells you what snapclient sees: playing · sync ±ms, waiting for server, or stopped.
  3. Optionally enable Start at boot under Show advanced — the daemon then starts on TV boot without opening the app.

Notes

  • Volume and client naming live on the server (Snapweb UI) — that's Snapcast's sync-safe design, v0.35+ removed client-side volume entirely.
  • The default 65 ms latency was measured on an LG G5; retune per TV model under Show advanced.
  • Packaged from the official Debian armel snapclient build with PulseAudio support; OpenSSL 1.1 / gcc-10 runtime libraries are bundled (webOS 9 ships OpenSSL 3).

Source & issues: malkstar/webos-snapclient — GPL-3.0, payload built from upstream Snapcast.
